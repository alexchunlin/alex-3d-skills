# Prior art: what was evaluated before writing cadcheck, cadq and cadlib

Measured 2026-10-24 on the attempt-1 outputs (copies in `/tmp/alex3d-a1`).

| Option | What it would replace | Measured | Result |
|---|---|---|---|
| Attempt-1 `checks.py` (the designer's own) | cadcheck | R1 re-ran it on the attempt-1 blend (`review/checks_rerun.json`): 35 parts manifold, 0 interference at 9 poses | Misses both R1 blockers. It excludes Fasteners and Cables, treats zero-volume contact as fine, and only checks nominal poses (0, 22.5, 45). Its manifold, wall, overhang and stability code was kept and extended in cadcheck. |
| trimesh 4 + manifold3d (`trimesh_compare.py`, via `uv run`) | per-part checks | 29 STLs in 0.16 s: all watertight, volumes match cadcheck, overhang area matches the unsplit figure (arm_cover_l 2707 mm²) | Fine for per-part checks, but STLs carry no assembly placement, joints, fasteners or purchased parts, so none of the 8 tool-catchable R1 issues can be expressed. Blender's `MANIFOLD` boolean solver is the same library, so staying in Blender costs no accuracy and needs no install. |
| Blender MCP server / persistent daemon (e.g. blender-mcp, a socket add-on in GUI Blender) | cold starts, interactive queries | Not installed. Instead I measured the cost it would remove: `Blender -b` cold start 0.69 s, loading the 6 MB blend 0.70 s; D1 spent 2.3 of 64 min in Blender (27 runs) | No speed case. One-shot `cad q` gives the same queries with no extra process, port or add-on. Revisit only if a GUI session is wanted for the user. |
| build123d / CadQuery (B-rep, STEP, robust fillets) | cadlib geometry | Not measured this run (needs OCP, a ~100 MB wheel) | Candidate for the aesthetics gap (R1 #16-17: inconsistent edge breaks, as Blender bevel-after-boolean is fragile). The next revision should measure fillet success on the attempt's parts before considering it. |
| Blender Mesh to Volume / Remesh + Laplacian smoothing, metaballs, convex hull + bevel (`blend_compare.py`, 2026-10-25) | `cadlib.blend` (grown connectors) | 6-way tube node, same exact socket cuts: fill 0.3-1.2 mm of the 2.49 mm r=6 crease with walls thinned to 2.99-3.84 (volume, remesh); metaballs 8.7 mm arm error and 1.6 mm wall; hull + bevel 2 non-manifold edges, 0 mm wall | None of them makes a dimensioned fillet. Details: `docs/features/blend-bracket.md`. |
| Blender SDF Grid Fillet (geometry nodes, OpenVDB) (`blend_compare.py`) | `cadlib.blend` | 70 iterations at voxel 0.5: fill 2.57 / 2.00 mm, wall 3.99, 6.9 s; the same 70 at voxel 0.25: fill 1.28 mm, 54 s | Close in looks, but the fillet size is a curvature-flow time, not a radius, and it is 5x slower. `blend` (numpy round union + OpenVDB mesher + Manifold cuts) gives 2.51 / 3.12 against the analytic 2.49 / 3.11 in 1.3 s. |
| Blender SDF closing: Mesh to SDF Grid, Offset +6, Offset -6 (geometry nodes) (`blend_compare.py` rows `a3_closing_*`, PR #4 second review) | `cadlib.blend` | radius 6 at voxel 0.5: fill 2.60 / 1.49 mm, wall 3.99, arm dev 0.013, 47-56 s against (e)'s 5.5 s in the same run (the reviewer: 57-62 s against 7.7 s) | The radius is a parameter here, so the choice rests on speed: 8-10x. It is a rolling-ball blend, so the 3-arm corner fills less; that is a look, not a fault. |
| Manifold union of poses (`sweep_compare.py`) | `geom.swept_envelope` | A3 nacelle over tilt -3..46: in-between poses poke out 2.28 / 0.91 / 0.46 mm at 5 / 2 / 1 deg steps; 7-part pod, 11 poses: not done after 10 min | The OpenVDB level set of all poses at +pad contains every tested pose (0 of 189,975 points out) in 2.3 s (pod: 9.7 s), at 0.37 mm mean oversize. |
| text-to-cad `dfam-check` (`dfam_tool.py measure`, 2f79365; `dfam_compare.py`, 2026-10-26) | `cad printcheck` | 36 shipped v2 STLs (`examples/mm-launcher-v2a7/stl.tar.gz`), 56 s, about 1.5 s per part. Area of off-bed downward faces flatter than 45 deg: catching printcheck's 4 fails needs a line at 200 mm2 or lower, which also flags 9 of the 32 passing parts (at 0 mm2: 23 of 32). turntable, which prints fine, ranks above every fail at 2,655 mm2. Its own sweep without the flat 0-10 deg bin (bridged ceilings) is worse (12 of 32 at 200). `watertight` is false on 5 parts that are manifold in Blender. Ramp (`ramp_stl.py`, underside 20 / 30 / 40 deg from horizontal): 426 / 462 / 522 mm2 where printcheck gives 0 fails, 0 warns | Can't replace printcheck: face area can't tell a bridge or anchored ledge from a cantilever, and dfam gives no verdict. It does measure exactly the gradual overhang printcheck passes, so it is the face-normal pass proposed in `docs/features/blend-bracket.md` ("The printcheck gap"), MIT, about 40 lines of numpy. Its wall p05 had no part under the 1.2 mm FDM line (min gate_detent 1.20). |
| Blender 3D-Print Toolbox extension 1.5.0 (projects.blender.org, bc94744; imported from a copy and registered for the run, not installed; `print3d_toolbox_compare.py`) | printcheck overhangs, cadcheck manifold and walls | Same 36 STLs, 26 s. Overhang counts faces, bed included, so it flags all 36. With its faces summed by area off the bed, the sweep matches dfam's (200 mm2: 4 of 4 fails, 10 of 32 passing). Ramp: 426 / 462 / 522 mm2, same as dfam. Solid: base_shell has 7 non-manifold edges in the STL, each shared by 4 faces (vertical edges on the outer walls at x, y = +-117). The model has 14 distinct vertices within 1 um there, which the float32 STL merges, and cadcheck counts 0. hood's 7 are zero-length edges that weld away at 1e-4. Thickness at 1.2 mm: thin faces on 23 parts, including jar_gate (1,593 mm2), whose sampled walls are all 1.4 mm or more (dfam min 1.4, p05 2.0) | No gain over dfam for overhangs. One real fact cadcheck misses: it checks topology on the model, not the exported STL, so a zero-thickness self-contact that only closes up in float32 passes. Small fix: count non-manifold edges on the STL in `cad printcheck`, which already reads it. The thickness ray flags walls that dfam measures above the line, so it isn't usable as a gate. |
| cadsmith `mech` clearance sweep (build123d 0.13 / OCC, 00c334d; `mech_export.py` + `mech_compare.py`, 2026-10-26) | cadcheck interference and joint sweeps | A1 blend, 13-15 parts exported in world home coordinates, imported to OCC in 2.9 s. Every printed part made a valid solid; each screw came in as 2 shells and failed BRepCheck, but its volume measured. One sweep (tilt, flywheel, feeder) took 32-40 s, against cadcheck's 70 s on the whole blend. A1-F3 cap screw under the feeder disc: FAIL 27.2 mm3 at home, 48.6 worst (cadcheck 48.6, the reviewer 27.2). A1-F5 at 45 deg: WARN 0.212 mm hopper / launcher_body (cadcheck 0.212, the reviewer 0.21) and 0.274 mm feeder_plate / launcher_cover (cadcheck 0.373; which is right is unchecked). Overtravel to 47.5: FAIL 38.9 / 14.6 / 6.1 / 0.06 mm3, the same as cadcheck, but only after widening the joint limits, since mech won't drive a joint past them. A1-F9 arm_cover_L / trunnion_L rub at 0 mm: not reported, because a pair on different joints that touches at home counts as joined and is exempt. With `check_clearance` declared for that pair: WARN 0 mm (cadcheck FAIL at 19 poses). A1-F10 reversed motor screws: FAIL 27.0 mm3 x 4, the same as cadcheck; head inside launcher_body shows as 35.8 mm3 "same rigid group, union them" | The closest prior art for cadcheck's sweep core. It matches cadcheck's interference and clearance numbers and proves the gaps between frames, which cadcheck samples. It can't replace cadcheck: its defaults miss A1-F9 (the class cadcheck was built for), it has no automatic overtravel, and it has no fastener semantics (head clear, tip in its own part, driver access), drop or feed test, slide-out, cables, per-pair running-fit minimum or `coverage` list. It also needs every part converted to OCC. Worth borrowing: the between-frame bound (chord plus a quarter of the bend) for cadcheck's step sizing. |

## Agent CAD repos surveyed, not measured (2026-10-26)

From their READMEs only. None of them describes a drop or feed test, screw access, fasteners checked against purchased
parts, slide-out, or a `coverage` list in its output.

- [LL3M](https://arxiv.org/pdf/2508.08228) (threedle; Blender Python): plan, retrieve, code, critic and verifier agents, plus a RAG over the
  Blender API docs. The critic reviews renders against the prompt, and a separate verifier checks that each fix was
  applied. That pattern fits `cad-design-review`'s check-first protocol, but the target is how an asset looks, not
  whether it works.
- [freecad_mcp](https://mcpservers.org/servers/bonninr/freecad_mcp) (bonninr): a socket bridge that runs Python in FreeCAD. It has the same shape as blender-mcp, so the verdict in
  the row above applies.
- [3d-print-modeling](https://github.com/m-esm/3d-print-modeling) (m-esm), [openscad-agent](https://github.com/iancanderson/openscad-agent) (iancanderson), andreahaku/openscad_claude_skill, wilsonwaters/3d-printing,
  fingerskier/build123d-claude-plugin, MikeSuiter/claude-build123d-starter, mfranzon/render: Claude Code skills built
  around a render, look and iterate loop on trimesh, build123d or OpenSCAD. Their checks are guidance or visual, so
  there's nothing to measure against cadcheck.
- text-to-cad's other skills: an off-the-shelf STEP part finder (screws, bearings, motors) is a possible source for
  `components/`; slicing through OrcaSlicer is out of scope (no usable slicer here, see `cad slice`).
