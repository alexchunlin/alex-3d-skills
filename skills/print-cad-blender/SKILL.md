# Print CAD in Blender

`<skill>` below is this folder. Tools live in `<skill>/scripts/`:

| Tool | Does |
|---|---|
| `cadlib/` | geometry + Manifold booleans (`geom`), print features (`features`), assembly conventions (`asm`), optional placement by mate connectors (`mates`), STL export (`export`), renders (`render`) |
| `cad build build.py -- args` | run a build script headless. A script that raises exits non-zero and prints `cad: BUILD FAILED`; `cad check` warns when sources are newer than the blend |
| `cad check model.blend checks.json` | every check below, JSON evidence plus a 40-line summary, about 2-40 s |
| `cad q model.blend <cmd>` | one measurement: `dist`, `sweep`, `ray`, `inside`, `list`, `section`, `render`. `cad q` alone prints the commands |
| `cad py -c "import params as P; print(P.X)"` | Python with bpy and cadlib, run from `blender/`: evaluate params or geometry helpers without stubbing bpy |
| `cad rows cadcheck.json [REGEX]` | one line per check row (or `manifest.json` part), no Blender: grep the report instead of writing a `json.load` snippet. v2 A3's agents wrote them in 67 bash calls, and 6 died on a guessed key |
| `cad bom BOM.md manifest.json` | the BOM's fastener table against the model: size, length, head, count, stock lengths |
| `cad mates manifest.json [REGEX]` | one line per interface (cadlib.mates): what mates with what, how, joint range, screws, fit. Grep it instead of re-deriving geometry |
| `cad sheet stl_dir out.png` | all STLs in print orientation on one image |
| `cad printcheck stl_dir [--manifest manifest.json] [--render DIR]` | layer-by-layer support check on the **exported STLs**: every unsupported region per 0.2 mm layer as a bridge (span), cantilever (overhang) or island, in print and world coordinates; `--render` writes a top-view map per flagged layer. `cad check`'s `parts` runs the same check, and `cad q m.blend printcheck PRT_x` runs it on one part |
| `cad slice stl_dir \| --detect` | a real slicer, sandboxed (no network, no printer, never your slicer settings) and crash-guarded (no crash dialogs): time, filament, warnings, and whether the slicer puts support under each part. It says plainly when no installed slicer is usable; then `cad printcheck` is the authority. The only way a slicer may be run |

Blender starts in 0.7 s, so run these as often as you like; Blender time was 2.3 of 64 min in the attempt that motivated this skill. Wall time goes on long single generations, so work in small steps.

## Workflow

1. **Plan checkpoint (first 10 minutes).** Read the brief and `<repo>/components/*.json` for purchased-part dimensions. Write the plan to the design log before modelling: world frame, subsystems, joints with ranges, the load path, the feed or payload path, the assembly order. Done when the log has a section per subsystem with its key dimensions. The killed attempt-0 designer lost 44 minutes because nothing reached disk.
   - Record the declared `EB`/`CR` and what the accent colour marks in the design log.
2. **Scaffold.** Copy `<skill>/templates/project/` into the project (`build_assembly.py` plus one module per subsystem under `parts/`, and `checks.json`). Each subsystem module is a few hundred lines that you edit in place. Writing one 80 KB script in a single generation took 5.4 min, and string-replace edits on it broke.
   - **Optional: `cadlib.mates`** (`reference/api.md` "mates"). Name a connector on each mating face and declare one mate per interface; `mates.assemble` places the parts, makes the joints and runs `fastener_joint` per hole. Use it when hole patterns must match a datasheet (it refuses a mismatch; a pitch typed 1 mm long passes `fastener_joint` and cadcheck) or when you want a searchable interface table (`cad mates`). It made no placement more accurate in A/B runs. The template places parts in world coordinates; `templates/project-mates/` is the mates version. A seated interface is `gap=0`: a fit's tolerance is never a gap.
3. **Build one subsystem at a time.** For each one: model it with cadlib, then `cad build`, then `cad check`. Fix every **fail** before starting the next subsystem, and append one line to `progress.md` (subsystem, check summary, time). Done when that subsystem has zero fails, and every warn on its objects is either fixed or listed under `accepted_warns` with a reason. v2 A1 finished at 0 fails and 34 warns, and three of the reviewer's issues were in those warns: a 0.94 mm wall at a self-tap pilot, a 0.40 mm magnet stack, and knife edges.
   - `G.bevel` before cuts that leave dense facets: Blender's overlap clamp is global, so one 0.28 mm facet shrinks every edge break on the part. cadlib prints a warning and cadcheck's `parts` warns when it happens (v2 A5-A6 detent tab: 0.1 instead of 1.0, V2A6-T2). A `distances` `min` at exactly the design value can fail by the chord sag of two faceted cylinders (A6: 0.969 against 1.0); give the cut a higher `n`.
   - **Joining.** Prefer snaps, press-fit pins, bayonets, captive tabs or printed hinges for parts that are neither serviced nor loaded; screws for load paths, service access and metal parts. Aim for one screw size and at most 3 lengths per design (the build's `FASTENERS` line counts them).
   - Place each screw with one `features.fastener_joint(name, "M3", at, into, [parts], style=...)` call. `at` is the head's bearing face; `into` is the direction the shank travels. It measures the stack, picks the stock length (bolts pass their nut, self-tap thread is at least 2 d), cuts every part, places the screw and nut, and raises if `into` is reversed or the thread is too short (A1-F10, A2-F3, A3-F5). Build the parts uncut and named `PRT_...`, then `geom.csg(part, sub=cuts[part.name])`.
   - Declare each joint with its real range (`asm.joint(..., lo, hi)`), and declare every designed running fit, thrust face and assembly step in `checks.json`. cadcheck fails anything undeclared, by design.
   - Model the payload path, then add a `drop_tests` entry with the landing window it must hit (`"mode": "slide"` when the payload slides down a chute).
   - Model nuts as `asm.nut()` (or name them `FST_*nut*`): cadcheck pairs each bolt with the nut on its axis and fails a bolt that stops short (A2-F3).
   - Turn every motion, timing or service claim into a check before it goes in the BOM: indexers into `index_tests`, "adjust without disassembly" into `service`, "comes off at tilt 45" into `slide_out`. In attempt 2 the double-feeding index and the "no disassembly" gap adjustment were prose nobody had run (A2-F2, A2-F6).
   - "Removable" means the whole path, not the rest pose. A `slide_out` sweeps the part out and counts fasteners in the way. In attempt 3, checks.py passed the battery at rest, but it slid through two adapter nuts (A3-F3).
   - Every printed spring, flexure or snap arm gets a `flexures` entry: the beam must lie in the layer plane. Attempt 3 printed its nip leaf spring standing up, so the bending stress ran across layer bonds (A3-F2).
   - Run payload tests at the **hard stops**, not just the firmware limits, and keep the flattest slide 5° above the stall angle. Attempt 3 fed 29/29 at tilt 45, but over a 21° slide with a 20° stall limit (A3-F1).
   - **Every adjuster gets tested at both ends of its travel:** drop tests, distances and service, not just the home setting. Give it real hard stops in the model. v2 A1's nip hinge was tested at home only. At one end the drop stalled, and at the other the hood hit the body (V2A1-F1). cadcheck now warns when a drop test holds a joint at home that moves a wall the payload touches.
   - **A pocket, slot or chute sized for the payload gets `payload_fit` rows at the payload's size limits:** two payloads must be blocked at the *smallest* size, and one must fit at the *largest*. v2 A1 and A2 both shipped a feeder pocket that seated two edge-on candies, and three agents wrote their own lentil probes (V2A2-F2).
   - **Write payload numbers as params expressions at the declared extremes**, not typed-in nominals: `"min": "=MM_T[1] + TAPE_T"`, `"size": ["=MM_D[0]", "=MM_T[0]"]`. v2 A3 declared candies up to 7.5 thick, sized the nip gap row for the nominal 7.0, and the reviewer's 7.5-candy row failed: the one major left (V2A3-F1).
   - **A gap the payload passes through is checked over the whole passage:** a `distances` ray with `"sweep"` (turned about the wheel axis over the gripped arc, or slid down a chute) reports the worst station and the profile. v2 A4's full-lift nip rows sat at BDC and passed at 8.28; the reviewer swept the entry arc and found 7.50 at psi 80, the one major left (V2A4-F1). Asserts in params (a `gap_bdc()` over ±2°) get the same rule.
   - **A gate, drawer or plunger is a `prismatic=True` joint**, so its open state is in every sweep. A detent that rides it goes in the slide row's `flex` with a bound in mm³, not in `ignore`. v2 A2 and A3 left the gate's open state unchecked and the reviewer moved it by hand (V2A3-T6).
   - **A clearance to a purchased part with a tolerance gets a `stacks` row with `"between"`**, so its limit is the measured gap, not a typed design intent. v2 A5's band stack read "designed radial clearance 3.0" and passed, while the new detent tab's own row had `min` 0.3 (every other band row 2.0) and sat 0.322 from the band: the one major (V2A5-F1). Give a riding detent or crush rib an `allow` with `max_mm3`, not an open `allow` (V2R5 A5-06).
   - **Conductors that run on through several cable routes get a `cable_chains` row** with the one purchased lead. v2 A3's 150 mm encoder lead "continued in the bundle" for 430 mm that no BOM row bought (V2A3-F3). Routes that meet across a joint meet **on its axis**; the `cables` drift warn shows how far an off-axis meeting comes apart (v2 A6: 8.8 mm at pan -90, V2A6-F2).
   - **Put each part in the step where it physically goes in, and give a step its `pose` when the BOM says "at +30" or "nose up 20".** The `insertion` check moves each part, and each bench group at its merge, out along a straight line past the earlier steps' parts. v2 A6 listed the bus splice (seated in the pan hub, under the groove cap) in the feeder's bench step; nothing flagged it, and it was the attempt's one major (V2A6-F1).
   - **A step that needs a joint moved after its servo is in says how.** Mark the step that brings power `"powered": true`; the `assembly` check warns on a step `pose`, or a screw reachable only at a joint limit, on a servo-held joint before that. v2 A7's groove-cap step said "tilt the pod to 45" six steps after the tilt servo and before the battery: back-driving an unpowered servo, the attempt's one major (V2A7-F1). Prefer a screw reachable at home; otherwise take the drive out first and write that in the step's `pose_how`.
   - **A removal row goes until the part is clear of the machine,** not 40 mm: v2 A7's cap row lifted +Z 40 and passed, but +Z hits the nip cover at 54 and the cap really leaves forward-up (V2R7 A7-03). The `insertion` check tests each part to infinity; a `slide_out` row should too.
   - **Model each lead as its own route, side by side in a shared channel, with one OD straight out of every plug or splice and corners rounded (at least 0.75 x OD on the centreline).** cadcheck warns on kinks and on two routes in one tube; v2 A7 had both at the bus splice (V2A7-F2).
   - Route cables with `cadlib.route` (`reference/route.md`), not typed waypoints; give each bore or slot a via with `"dir"`.
   - Cross a joint along its axis (via `"dir"` = the axis) or model a service loop: across a hinge axis the cable folds by the hinge angle.
   - Turn "reachable through the slot" or "visible through the window" into a `sightlines` row, and "stops at 52" into a `slide_out` row with `"expect": "blocked"`. A `cad q ray` line proves it once; a row re-proves it on every run (V2A2-T4).
   - Each **hard stop** gets a `distances` row at the joint limit with `max` about 0.1, naming the two parts that touch. In v2 A2 the leaf-lift limit said "the stud bottoms on the cover", but the stud was 2.36 mm clear there (V2A2-F1).
   - A `fits` rule with `contact: true` covering a thrust or stop face **and** a journal needs `contact_normal`. Otherwise the journal is never measured (V2A1-V4).
   - For organic multi-tube nodes and swept keep-outs for moving parts, see `reference/blend.md`. Orient grown parts with `blend.best_orientation`; `cad printcheck` is the authority.
   - For an adjuster modelled at one setting (for example a thumbwheel on a stud), `carry` it onto the joint it rides on. List a captive stud under `fasteners.captive`. Don't `allow` its clashes (A3-V1).
4. **Renders.** Make preview renders only after checks pass (`render.view_set`, 960 px). Then look at sections through the critical interfaces (`cad q ... section`, with `--lentil` markers for the payload). Render the final 1600 px+ set once, at the end (`CAD_RENDER_FINAL=1`).
5. **Report evidence, not verdicts.** **"supports: no" is a claim, and it needs evidence:** `cad printcheck <project>/stl --manifest blender/manifest.json` with 0 fails (and `cad slice <project>/stl` when a slicer is usable: `slicer adds support to: none`). v2 shipped every part as supports: no; jar_valve's three bayonet tabs (5.5 mm cantilevers at z 2), feeder_cover's screw ears (10.5 mm at z 32), base_shell's zip-tie block (6 mm) and post_R's top above the cover split (11.7 mm) needed support, and no check failed (FINDINGS "v2 post-freeze"). A part that really needs support says `supports: "yes"` and where in `orient`. Run `cad bom` on the BOM before hand-off (v2 A3's BOM gave the stud as M3 x 20 hex while the model had M3_cap x 16, V2A3-F6). Hand over the `cadcheck.json` summary: fails, warns, `coverage`, `not_checked`. Every claim in the design log cites a check row or a `cad q` line. Attempt 1 reported "zero interference" while fasteners and cables were excluded and contacts ignored.

## Conventions (cadcheck and the web viewer depend on these)

- World X right, Y forward (front/muzzle), Z up, units mm, origin on the table under the main axis.
- Collections `Printed`, `Purchased`, `Fasteners`, `Cables`. Names are `PRT_`, `BUY_`, `FST_`, `CAB_` plus the part name.
- Moving links hang under `PIV_<joint>` empties made by `asm.joint`. Mesh data is baked in world coordinates at the home pose. Things that rotate with a shaft (rotor, magnet, wheel) belong to the shaft's joint, not the stator's.
- Every `PRT_` carries `stl`, `print_rot`, `orient`, `supports` and `infill` (`asm.part` refuses without them). Every `BUY_` carries `mass_g` and `src`.
- `asm.write_manifest()` writes parts, joints, fasteners, cables, features and parameters (and mates and connectors when used), so a reviewer reads JSON instead of your script.

## What cadcheck covers

parts (manifold, bed fit, sloped overhang, wall probe, bed contact, and the **layer support check** on the exported STLs: islands and cantilevers over 3 mm fail on supports: no, ledges of 1-3 mm and bridges over 25 mm warn) · interference over **all four** collections, swept over the joints between each pair plus 2.5° of overtravel · contacts across a joint · clearance below 0.5 mm · fasteners: head buried, a head or nut overlapping a part on its body, thread engagement, bolt-to-nut engagement, shanks or nuts inside purchased parts, head stand-off, protruding thread, access with a straight bit or an L-key at the step it is installed (and at the wheel angles you can turn it to) · service ops on the built machine · drop paths (straight rays or fall-and-slide) with angle windows · indexer timing · slide-out of a part or a group · distances (nearest, or a gap along a ray or a swept ray, with payload squeeze; a ray that lands on another face than at home warns), with `=EXPR` values from the params · payload fit (two payloads blocked, one fits, with the size margin) · sightlines (first hit along a finger, tool or view ray) · assembly config (objects in no step, step labels whose screw size disagrees with the model) · straight-line insertion of each part and each merged bench group past the earlier steps, and bench parts far from their group · tolerance stacks · springs and snap arms against print orientation (`flexures`) · CG tip angle · cable length, cable chains and connector-less junctions, cable ends that come apart across a joint, kinked corners and two routes in one tube, held poses (a step that moves a servo-held joint before power), exposed cable and visible nuts · stocked screw lengths · prismatic (slide) joints in every sweep.

It also lists what it did **not** check (teardown count, slack across joints, wrench access to nuts, aesthetics beyond exposure). Cover those with sections and the design log. A full run on the 119- to 122-object attempt-2 and attempt-3 assemblies takes 58-64 s; use `--only fasteners,service` while iterating.

## Reference

- `reference/api.md`: cadlib functions and their arguments. Read it before writing the first part.
- `reference/checks-config.md`: `checks.json` schema (joints, carry, fits and contact_normal, allow, captive fasteners, assembly_order with nested bench merges, service, drop_tests, index_tests, slide_out (with expected stops), distances, payload_fit, sightlines, stacks, flexures, exposure, masses, accepted_warns) plus `--only`/`--overlay`. Read it when cadcheck flags something you designed on purpose, **before** reading cadcheck.py: v2 A1 agents spent minutes in the source on bench merges and slide semantics.
- `reference/design-principles.md`: form language (one section, continuing lines, colour roles). Worth reading when you choose it for a new project.
- `reference/footguns.md`: the mistakes from attempts 1-3 and the check that catches each. Read it before declaring a subsystem done.
- PLA rules (pilot 2.5, clearance 3.4, nut 5.7 AF, fits, bridge 25 mm): `cadlib/features.py RULES`.
